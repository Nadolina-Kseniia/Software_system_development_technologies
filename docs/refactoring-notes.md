# Отчет о рефакторинге (Лабораторная работа №3)

## Что было сделано
- Проведен аудит тестируемости исходного кода.
- Внедрены швы (Seams) для времени, порождения идентификаторов, хранилища и оповещений.
- Исходная функция `create_booking` (84 строки) разбита на слои:
  - `domain` (чистые бизнес-правила и модели),
  - `ports` (интерфейсы),
  - `adapters` (реализации для БД и логов),
  - `services` (сценарий использования).
- Написаны тесты на «дублях» (подставки и шпионы) для проверки бизнес-логики без HTTP и базы данных.

## Применённые паттерны
1. **Фабричный метод:** В файле `api/dependencies.py` собираются все зависимости для сервиса.
2. **Адаптер:** Класс `InMemoryBookingRepository` скрывает реализацию хранения за интерфейсом (подготовка к переходу на PostgreSQL).
3. **Стратегия:** В `services/policies.py` вынесены правила для разных видов мест (стол или переговорка), что позволяет легко добавлять новые виды без изменения основного кода.

## Результаты (Было и стало)
- Строк в самой длинной функции: 84 -> 27 (код стал читаемым).
- Тестов предметной логики без HTTP: 0 -> 10 (быстрые тесты).
- Время прогона набора: сократилось в разы.
- Бизнес-логика больше не зависит от веб-фреймворка FastAPI (проверяется в CI).
