# 4. Использование JWT-токенов для аутентификации

- **Статус**: принято
- **Дата**: 2026-10-15
- **Участники**: вся команда

## Контекст

Системе нужно различать роли (Водитель и Владелец гаража) и защищать эндпоинты от несанкционированного доступа. 
Водитель должен иметь возможность управлять только своими бронями, а Владелец — только своими гаражами. При этом мы разрабатываем веб-приложение (ограничение `C-03`), и у нас нет выделенного сервера для хранения сессий (например, Redis) на этапе MVP.

## Движущие факторы

- `NFR-02`: Управление броней и генерация QR-кода требуют авторизации.
- `C-04`: Команда из двух человек, ограниченное время — нужно простое в реализации решение.
- `C-03`: Только веб-клиент, мобильных приложений нет.

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| **JWT (JSON Web Tokens) + Refresh Token** | Stateless (не требует хранения сессий на сервере), легко масштабируется, стандарт для FastAPI | Сложно отозвать токен до истечения срока действия (нужен "черный список") |
| Сессии на основе Cookie (Session ID) | Мгновенный отзыв сессии, безопаснее | Требует хранения состояния на сервере (в БД или Redis), что усложняет архитектуру |
| OAuth 2.0 (вход через Госуслуги/VK) | Не нужно хранить пароли | Избыточно для учебного проекта, требует регистрации приложения и внешних интеграций |

## Решение

Выбрана схема с использованием **JWT (JSON Web Tokens)**. 
При успешном логине сервер выдаёт два токена:
1. `access_token` (срок жизни 15 минут) —用于 авторизации запросов.
2. `refresh_token` (срок жизни 7 дней) —用于 получения нового `access_token`.

**Определяющий довод** — отсутствие необходимости разворачивать дополнительную инфраструктуру (Redis) для хранения сессий, что критично при ограниченном времени (`C-04`). Токены будут передаваться в заголовке `Authorization: Bearer <token>`.

## Последствия

**Положительные.** 
Сервер не хранит состояние пользователя (stateless). Легко реализуется с помощью библиотеки `python-jose` или `fastapi-users`. Упрощается горизонтальное масштабирование.

**Отрицательные.** 
Невозможно мгновенно "разлогинить" пользователя или отозвать доступ (например, при краже токена) до истечения 15 минут. 
Пароли нужно хранить в виде хеша (будем использовать `bcrypt`).

**Что пересмотрит решение.** 
Если появятся требования к безопасности, предписывающие мгновенный отзыв доступа (например, при блокировке пользователя), придется внедрить хранение "черного списка" токенов в Redis или перейти на серверные сессии.
